# INIT 홈페이지 디자인 구현 프롬프트

아래 지시를 기준으로 `initgroup-homepage`의 디자인을 실제 운영 소스에 구현한다. 분석이나 제안서 작성만으로 끝내지 말고, 소스 수정과 브라우저 검증까지 완료한다.

## 1. 목표

`templates/design/`에 있는 PNG 시안, CSS, HTML, Markdown 디자인 가이드를 참고하여 현재 홈페이지와 시안을 해상도별로 비교하고, 차이가 큰 레이아웃·색상·간격·타이포그래피·배경 표현을 실제 운영 코드에 반영한다.

대메뉴별 첫 화면만 바꾸는 데 그치지 않고, 각 대메뉴의 디자인 언어가 해당 하위 메뉴, 앵커 섹션과 상세 페이지에도 일관되게 이어지도록 구현한다.

## 2. 가장 중요한 원칙

1. 현재 저장소의 콘텐츠, 메뉴 구조, URL과 기능이 기준이다. 디자인 참고 문서가 현재 소스와 충돌하면 현재 소스와 이 프롬프트를 우선한다.
2. `templates/design/`은 삭제 예정인 임시 참고 폴더다. HTML, CSS, JavaScript에서 이 폴더의 파일을 직접 참조하거나 import하지 않는다.
3. 실제 화면에 필요한 이미지는 `assets/images/` 아래의 의미 있는 운영 경로로 복사한 후 그 경로만 사용한다.
4. 참고 CSS 전체를 그대로 가져오지 않는다. 전역 reset, 작은 글자, 헤더 높이, 메뉴 동작 등 기존 시스템을 훼손할 수 있는 규칙은 선별적으로 이식한다.
5. 기존 상단 헤더, 전체 메뉴, 호버 메뉴, 모바일 메뉴, 서브 메뉴, 현재 위치 표시와 활성 상태를 유지한다.
6. 기존 URL, 앵커 ID, 내부 링크, 다운로드, `mailto:`, `tel:`, 다국어 키와 페이지별 기능을 유지한다.
7. 공개 승인되지 않은 고객명, 실적, 수치, 인증, 채용 공고나 광고성 문구를 새로 만들지 않는다.
8. 외부 CDN, 새 UI 프레임워크, npm 또는 번들러를 필수 실행 조건으로 추가하지 않는다.
9. 기존 사용자의 변경사항을 되돌리지 않는다. 작업 전에 반드시 `git status --short`로 변경 범위를 확인한다.
10. 사용자가 명시적으로 요청하지 않으면 `git add`, `git commit`, `git push`를 실행하지 않는다.

## 3. 반드시 수행할 작업

### 단계 A. 기준 화면과 참고 자료 조사

1. `git status --short`와 `rg --files templates/design`으로 현재 변경사항과 참고 자료를 확인한다.
2. `templates/design/`의 관련 PNG를 실제로 열어 시각적으로 확인한다.
3. 관련 CSS, HTML과 Markdown 문서는 필요한 범위까지 읽고 다음 항목을 추출한다.
   - 페이지별 색상과 명암 체계
   - 배경 이미지와 그래픽 모티프
   - 콘텐츠 정렬과 컬럼 구조
   - 제목 크기와 줄바꿈
   - 섹션 간 간격과 경계
   - 카드, 버튼, 표, 제품 화면의 표현 방식
   - 데스크톱과 모바일의 차이
4. 현재 홈페이지를 로컬 서버에서 실행하고 수정 전 기준 화면을 캡처한다.
5. 최소 `1920`, `1440`, `1024`, `768`, `430`, `390`, `360px` 너비를 점검한다.

### 단계 B. 시안과 현재 화면 비교

페이지마다 다음 비교표를 내부 작업 기준으로 만든다.

| 비교 항목 | 참고 시안 | 현재 화면 | 수정 필요 여부 |
|---|---|---|---|
| 전체 배경과 색상 |  |  |  |
| 히어로 높이와 정렬 |  |  |  |
| 제목 크기·줄바꿈 |  |  |  |
| 본문 폭과 가독성 |  |  |  |
| 버튼과 주요 행동 |  |  |  |
| 이미지 위치·크기 |  |  |  |
| 섹션 간격·경계 |  |  |  |
| 모바일 재배치 |  |  |  |
| 메뉴·현재 위치 |  |  |  |

단순히 색상만 바꾸지 말고 시안과 차이가 큰 구조, 여백, 시각적 위계부터 수정한다.

### 단계 C. 운영 자산으로 분리

1. 채택할 PNG 또는 SVG만 `assets/images/` 아래의 운영 경로로 복사한다.
2. 파일명은 페이지 또는 용도가 드러나게 정리한다.
3. 복사한 파일이 원본과 동일한지 크기나 해시로 확인한다.
4. CSS의 `url()`과 HTML의 `src`에는 `/assets/...` 루트 경로만 사용한다.
5. 다음 문자열이 운영 코드에 남지 않았는지 검사한다.

```powershell
rg -n "templates/design|templates\\design" templates assets site_config.py main.py
```

검색 결과가 없어야 한다. 참고용 `templates/design/` 내부 문서에 경로가 적혀 있는 것은 허용하지만 운영 템플릿과 자산에서는 금지한다.

### 단계 D. HTML·CSS·JavaScript 구현

1. 기존 템플릿의 의미 구조와 콘텐츠를 최대한 유지하면서 필요한 래퍼와 클래스만 정리한다.
2. 공통 디자인 토큰은 기존 CSS 변수에 통합하고 중복된 디자인 시스템을 만들지 않는다.
3. 대메뉴별 디자인은 색상 포인트만 다른 복제품이 되지 않도록 배경, 첫 두 섹션의 구조와 시각적 모티프를 구분한다.
4. 현재 참고 자료가 해당 콘셉트를 제공하면 다음 계열을 기본 방향으로 사용한다.
   - 회사: 민트·화이트 기반의 신뢰감 있는 기업·연혁 표현
   - 서비스: 블루·블루그레이 기반의 연결된 수행 체계
   - 솔루션: 네이비 기반의 제품·플랫폼 무대와 실제 UI 중심 표현
   - 프로젝트: 바이올렛·앰버 기반의 결과 중심 사례집
   - 인사이트: 따뜻한 종이색 기반의 편집·매거진 표현
   - 채용: 라벤더·화이트 기반의 사람·성장 네트워크
5. 하위 앵커와 상세 페이지에도 상위 대메뉴의 색상, 배경, 카드와 제목 체계를 이어 적용한다.
6. JavaScript 수정은 실제 상호작용에 필요한 경우만 수행한다. CSS로 가능한 표현을 불필요하게 JavaScript로 만들지 않는다.
7. 키보드 포커스, skip link, `aria-current`, `aria-expanded`, `prefers-reduced-motion`을 유지한다.
8. 모든 문서에 정확히 하나의 `main`과 `h1`이 유지되게 한다.

## 4. 타이포그래피와 반응형 기준

1. 실제 표시되는 글자는 모든 해상도에서 `16px` 미만으로 줄이지 않는다.
2. 제목은 지나치게 광고 문구처럼 커지지 않게 조절한다.
   - 데스크톱 히어로 제목 권장 최대: 약 `60px`
   - 모바일 히어로 제목 권장: 약 `40~48px`
3. 본문은 `16~18px`, 카드 제목은 `20~24px` 범위를 기본으로 한다.
4. 한국어 제목과 문장은 `word-break: keep-all`을 우선하고 어색한 한 글자 줄바꿈을 방지한다.
5. 모바일에서 데스크톱 레이아웃을 단순 축소하지 말고 컬럼, 순서, 이미지 위치와 간격을 재구성한다.
6. 모든 목표 해상도에서 가로 스크롤이 없어야 한다.
7. 배경 시각물이 텍스트 대비를 해치지 않도록 오버레이와 배경 위치를 해상도별로 조정한다.

## 5. 반드시 보존할 메뉴와 기능

다음 항목은 디자인 수정 이후에도 동일하게 동작해야 한다.

- 데스크톱 상단 대메뉴와 현재 대메뉴 활성 표시
- 상단 메뉴 호버로 여는 전체 메뉴 구조
- 메뉴 팝업 내부로 마우스를 이동할 때 닫히지 않는 동작
- 링크 클릭 후 이동한 페이지에서 메뉴가 다시 의도치 않게 열리지 않는 동작
- 우측 전체 메뉴 버튼의 열기·닫기
- 모바일 메뉴 열기·닫기와 모든 메뉴 표시
- 서브 메뉴 바와 현재 하위 메뉴의 활성 표시
- 서브 메뉴의 가로 스크롤과 모바일 터치 이동
- 홈에서도 확보하는 공통 서브 메뉴 높이와 메뉴 팝업의 Y축 시작 위치
- 한국어·영어 전환
- 고정 상담 버튼과 모바일 하단 행동 버튼
- 모든 내부 링크, 앵커, 다운로드와 연락 링크

## 6. 다국어 처리

화면 문구를 추가하거나 한국어 원문을 변경했다면 다음을 수행한다.

```powershell
.\venv\Scripts\python.exe scripts\i18n_catalog.py --sync
```

생성된 동일 키의 영어 값을 `assets/i18n/en.json`에 자연스럽게 작성한 뒤 다음 검사를 통과시킨다.

```powershell
.\venv\Scripts\python.exe scripts\i18n_catalog.py --check
```

JavaScript에서 새 문구를 생성할 때 언어를 조건문으로 하드코딩하지 말고 `window.INIT_I18N.t()`를 사용한다.

## 7. 구현 후 시각 비교와 반복 개선

1. 구현 후 수정 전과 동일한 해상도로 다시 캡처한다.
2. 참고 시안, 수정 전 화면, 수정 후 화면을 나란히 비교한다.
3. 다음 차이가 남아 있으면 최소 한 번 더 수정하고 재검증한다.
   - 히어로 시각적 비중이 시안과 크게 다름
   - 제목과 배경 이미지가 겹침
   - 섹션 시작 위치나 간격이 불규칙함
   - 페이지별 디자인 구분이 색상 외에는 보이지 않음
   - 모바일에서 이미지가 잘리거나 콘텐츠가 고정 버튼에 가림
   - 현재 메뉴와 서브 메뉴 위치가 명확하지 않음
4. 시안의 모양을 맞추기 위해 접근성, 실제 콘텐츠, 메뉴 기능이나 반응형 동작을 희생하지 않는다.

## 8. 최종 검증

가능한 범위에서 다음 검사를 실행한다.

```powershell
.\venv\Scripts\python.exe scripts\build_site.py --check
.\venv\Scripts\python.exe scripts\i18n_catalog.py --check
node --check assets/js/site.js
git diff --check
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\validate.ps1
```

브라우저 검사에서는 최소 다음을 확인한다.

- 모든 공개 페이지 HTTP 응답 정상
- 콘솔 오류와 요청 실패 없음
- 깨진 이미지 없음
- `16px` 미만 표시 글자 없음
- 가로 오버플로 없음
- 데스크톱 호버 메뉴와 전체 메뉴 동작 정상
- 모바일 메뉴와 서브 메뉴 동작 정상
- 대메뉴와 하위 메뉴의 `aria-current` 정상
- 메뉴 팝업이 페이지 콘텐츠를 의도치 않게 계속 가리지 않음
- `prefers-reduced-motion`에서 불필요한 애니메이션 중지

검증 도중 기존 임시 파일의 잠금이나 외부 환경 문제를 만나면 잠긴 파일을 강제로 삭제하지 않는다. 통과한 항목과 막힌 항목을 구분하고, 별도 출력 경로나 읽기 전용 검사로 안전하게 보완한다.

## 9. 완료 보고 형식

최종 답변에는 다음만 명확하게 정리한다.

1. 대메뉴별로 무엇이 달라졌는지
2. 하위 메뉴와 상세 페이지에 디자인이 어떻게 이어졌는지
3. 운영 경로로 복사한 이미지와 주요 수정 파일
4. 보존한 메뉴·URL·다국어·모바일 기능
5. 해상도별 시각 검사와 기능 검증 결과
6. `templates/design/` 런타임 참조가 없는지 여부
7. 남아 있는 환경상 검증 제한이나 후속 확인 항목
8. Git 커밋과 푸시를 실행하지 않았다는 사실

## 10. 완료 조건

다음 조건을 모두 만족해야 작업을 완료로 판단한다.

- 시안과 현재 화면을 해상도별로 실제 비교했다.
- 레이아웃·색상·간격·타이포그래피의 큰 차이를 운영 소스에 수정했다.
- 필요한 참고 이미지를 `assets/images/`로 복사했다.
- 운영 코드가 `templates/design/`을 참조하지 않는다.
- 메뉴, 현재 위치, URL, 다국어와 모바일 기능이 유지된다.
- 대메뉴 디자인이 하위 앵커와 상세 페이지까지 이어진다.
- 구현 후 다시 캡처하여 시안과의 차이를 점검하고 필요한 보정을 수행했다.
- 오류, 깨진 이미지, 가로 스크롤과 `16px` 미만 글자가 없다.
- 분석 보고만 제출하지 않고 실제 파일 수정과 검증을 끝냈다.
