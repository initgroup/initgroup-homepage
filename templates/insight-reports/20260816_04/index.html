데이터 검증에서 규칙과 AI를 하나만 선택해야 한다고 생각하기 쉽습니다. 하지만 두 방식은 잘하는 일이 다릅니다. 업무 정의가 확정된 경우에는 규칙이 일관된 통제를 제공하고, 새로 나타나는 변화나 복합적인 패턴에는 AI가 검토 후보를 넓혀줍니다.

중요한 것은 어느 쪽이 더 똑똑한가가 아니라, 각 결과가 어떤 상태로 다음 검토에 넘어가며 사람의 판단이 어떻게 개선에 반영되는지를 설계하는 일입니다.

01 / TWO ROLES

확정 기준과 탐색 신호를 구분합니다

형식, 허용 코드, 필수값, 업무상 앞뒤 관계처럼 기준을 문장으로 합의할 수 있는 항목은 규칙으로 관리합니다. 규칙에는 적용 범위, 예외 조건, 근거와 담당자를 함께 기록해야 합니다.

반면 아직 기준을 모두 정의하기 어렵거나 여러 변수의 조합에서 나타나는 변화는 AI·통계 모델이 후보를 찾도록 합니다. 이 후보는 오류 확정이 아니라, 왜 검토가 필요한지와 얼마나 우선할지를 알려주는 신호여야 합니다.

규칙 기반
합의된 기준을 반복 적용하고, 위반 이유를 명확하게 설명합니다.
AI 기반
분포 변화·복합 패턴에서 사람이 살펴볼 후보와 우선순위를 제안합니다.
전문가 검토
원천 맥락과 예외를 확인해 채택·수정·제외·보류를 결정합니다.
개선 이력
결정 결과를 모아 규칙 범위와 모델 성능을 함께 조정합니다.

02 / REVIEW FLOW

같은 검토 흐름에서 결과를 비교합니다

규칙 위반과 AI 후보를 각각 다른 파일과 화면에서 관리하면, 담당자는 결과를 비교하기 어렵고 개선 근거도 흩어집니다. 검토 대상, 원본 값, 판단 근거와 처리 결과를 같은 식별자 아래 연결해야 합니다.

  1. 01탐지

    규칙과 모델이 각각의 근거, 버전과 우선순위를 포함해 후보를 만듭니다.

  2. 02정렬

    영향도·신뢰도·업무 마감 등을 기준으로 검토 순서를 정합니다.

  3. 03판단

    담당자가 원본과 맥락을 보고 채택·수정·제외·보류를 결정합니다.

  4. 04개선

    결정 사유와 반복 패턴을 규칙·모델 개선 후보로 다시 연결합니다.

03 / OPERATING METRICS

정확도 대신 운영에 도움이 되는지를 측정합니다

AI 검증의 성능은 정답률 하나로 판단하지 않습니다. 중요한 오류를 얼마나 앞에 보여줬는지, 담당자가 근거만으로 판단할 수 있었는지, 잘못된 후보가 검토 시간을 얼마나 차지했는지를 함께 봅니다.

  • 각 검증 결과가 규칙·모델 버전과 데이터 기준일을 포함하는가?
  • 후보의 우선순위가 업무 영향과 검토 가능성을 반영하는가?
  • 오탐·누락과 담당자의 수정 사유를 구조화해 저장하는가?
  • 규칙과 모델 변경 전후의 처리 시간·결정 일관성을 비교하는가?
  • 자동 수정이 필요한 경우에도 되돌리기·승인·원본 보존 기준이 있는가?
