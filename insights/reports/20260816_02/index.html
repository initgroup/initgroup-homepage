REPORT / 20260816_02

생성형 AI를 업무에 연결하기 전 확인할 4가지 기준

검색 범위, 출처 표시, 권한과 최신성 관리를 기준으로 생성형 AI 적용 범위를 설계합니다.

  • 인아이티 인사이트
  • 2026.08.16
  • 기술·AI
  • 6 min read
ONE SENTENCE

생성형 AI의 첫 설계 대상은 프롬프트가 아니라, 답변이 어떤 근거와 권한 위에서 만들어질지를 정하는 일입니다.

먼저 읽기
01

질문별로 허용된 지식 범위와 답변이 필요한 근거 수준을 정의합니다.

02

출처, 권한과 최신성은 모델 밖에서 관리하고 답변 화면까지 전달합니다.

03

자동 응답·초안·검토 보조를 업무 위험과 되돌릴 수 있는 수준에 맞춰 나눕니다.

CONTENTS
  1. 답변의 범위 정하기
  2. 출처·권한·최신성
  3. 업무 흐름에 넣기

생성형 AI는 질문을 자연스러운 문장으로 바꾸고, 여러 자료를 요약해 초안을 만드는 데 강점이 있습니다. 하지만 업무에 연결되는 순간 “그럴듯한 답변”만으로는 부족합니다. 어떤 자료를 볼 수 있고, 근거를 어디까지 보여야 하며, 누가 결과를 확정하는지가 함께 정해져야 합니다.

도입을 시작할 때는 모델이나 프롬프트를 먼저 고르기보다, 답변의 범위와 검토 수준을 정하는 네 가지 기준을 마련하는 편이 좋습니다.

01 / ANSWER SCOPE

무엇에 답할지보다, 무엇에는 답하지 않을지 먼저 정합니다

AI가 참조하는 지식의 범위는 업무별로 달라야 합니다. 최신 공지와 확정된 매뉴얼만 답변에 사용할지, 과거 사례까지 참고할지, 초안 작성에만 사용할지를 질문 유형별로 정합니다. 범위가 분명하면 답변하지 말아야 하는 요청도 투명하게 안내할 수 있습니다.

정보 조회
확정된 문서에서 사실과 절차를 찾고 출처를 함께 보여줍니다.
초안 작성
사용자가 제공하거나 승인된 자료를 바탕으로 문안을 만들고 검토를 전제로 합니다.
업무 판단
결론을 확정하지 않고 필요한 근거, 누락 정보와 검토 담당자를 제안합니다.
제한 응답
권한 밖 정보, 최신성이 불명확한 자료와 민감한 결정은 답변 범위에서 제외합니다.

02 / EVIDENCE AND CONTROL

출처·권한·최신성은 답변 밖에서 통제합니다

모델이 출처를 기억하게 하는 방식은 신뢰할 수 없습니다. 검색 대상 문서의 승인 상태, 유효 기간, 접근 권한을 별도로 관리하고, 답변을 만들 때 이 조건을 통과한 자료만 쓰게 해야 합니다.

사용자는 답변 문장과 함께 문서명, 기준일과 원문 위치를 확인할 수 있어야 합니다. 자료가 없거나 서로 충돌하면 AI가 단정하지 않고, 확인이 필요한 지점과 담당 경로를 제시해야 합니다.

출처가 없는 자신감은 업무에서 가치가 없습니다. 답변의 한계도 근거처럼 보여줘야 합니다.

03 / WORKFLOW

위험과 되돌릴 수 있는 수준에 맞춰 업무 흐름에 넣습니다

초기에는 반복되는 문의의 자료 찾기, 보고서 초안 구조화, 검토 항목 정리처럼 사람이 최종 결과를 쉽게 확인할 수 있는 흐름부터 시작합니다. 자동 발송이나 승인·지급처럼 영향이 큰 결과는 별도의 검토와 권한 절차 없이는 연결하지 않습니다.

  • 질문 유형별로 허용 자료, 금지 자료와 필요한 출처 표시 수준을 정했는가?
  • 문서의 승인 상태·유효 기간·접근 권한을 검색 전에 확인하는가?
  • 근거가 없거나 충돌할 때 답변을 제한하고 확인 경로를 안내하는가?
  • 초안·추천·확정 결과의 상태를 구분하고 최종 책임자가 정해져 있는가?
  • 자주 발생하는 수정·제외 사례를 지식 갱신과 프롬프트 개선에 반영하는가?

FINAL THOUGHT

좋은 답변은 모델 성능보다 운영 기준에서 시작됩니다

생성형 AI는 빠르게 문장을 만들 수 있지만, 업무 신뢰는 답변의 범위와 근거를 명확히 할 때 생깁니다. 작은 검토 보조부터 시작해 실제 예외와 책임을 기준으로 범위를 넓히는 편이 안전합니다.
